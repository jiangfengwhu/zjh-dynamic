# 用户动态

平台用户动态与插件本地动态独立存储，在动态页按时间合并。「用户」标签只显示公开用户帖子。匿名可浏览，发帖入口登录成功后回到编辑页；只允许作者删除自己的帖子。

首版支持文字（最多 2000 个 Unicode 字符）和最多 4 张图片，可仅发图片。图片由 image-crop-picker 缩放压缩，单张上传上限 3 MiB，文件传输沿用 BlobUtil，存储在 R2。FastImage 显示缩略图和大图。账号凭证仅由宿主传输层使用，不提供给插件。

接口由独立 Posts Durable Object 提供，使用现有 Accounts 验证身份、读取公开头像昵称。DO 的部署声明新增存储类型，不进行旧业务数据迁移。

- GET /v1/posts：匿名分页，50 条一页，稳定时间及 ID 游标。
- PUT /v1/post-media：登录上传图片，返回图片 ID 与 URL。
- POST /v1/posts：发布正文、图片 ID、请求 ID，作者身份由服务端会话决定。相同请求 ID/内容返回同一帖子，内容变化不能复用请求 ID。
- DELETE /v1/posts/:id：作者删除，删除关联图片；失败的图片清理由定时任务重试。
- GET/HEAD /v1/post-images/:owner/:id：公开图片读取。

服务端限制发帖频率、校验图片归属及格式。未附到帖子的上传图片在 24 小时后由定时任务清理。清库入口同步清理用户动态与图片。客户端缓存公开时间线，刷新和分页不会覆盖刚发布/删除的结果；编辑文字按账号保存草稿，上传失败时保留编辑内容，已上传图片可复用重试。

用户帖子采用 Twitter 风格的头像、正文与互动栏布局。点击正文或评论按钮进入详情；评论、回复评论、点赞需要登录，浏览和系统分享无需登录。本人帖子和评论的删除入口统一放在右侧「…」菜单，删除前确认。点赞数量与本人状态存储在服务端，账号切换时清除缓存中的本人点赞状态。

- GET /v1/posts/:id：一次返回帖子、首批评论、计数和本人点赞状态；评论按时间升序，每页 50 条。
- GET /v1/posts/:id/comments?cursor=...：评论分页，响应同时包含帖子最新计数。
- POST/DELETE /v1/posts/:id/like：幂等点赞或取消点赞。
- POST /v1/posts/:id/comments：正文最多 1000 个 Unicode 字符、请求 ID、可选 replyTo。同一请求重试不会重复评论；回复在平铺评论列表中标注被回复人。
- DELETE /v1/posts/:id/comments/:commentId：仅评论作者可以删除。
- GET/HEAD /posts/:id：分享链接公开网页，展示正文及图片；已删除帖子显示不可用提示。

计数与评论写入采用事务，同一帖子的互动和删除串行处理。删除帖子同步删除评论、点赞记录；删除评论保留已发表回复及被回复人的名称。暂未实现关注和站内转发。

动态可附带一个本人已上架的应用，也可以只分享应用。编辑页从公开市场读取本人作品；POST /v1/posts 可携带 application: {appId, releaseId}，服务端查询权威市场条目，核对作者及当前公开版本，展示信息由服务端生成，拒绝候选包、他人应用、已撤回或已变更的公开版本。动态保留当时的名称、介绍和版本快照，点击卡片通过 GET /v1/market?appId=... 读取当前市场详情；撤回应用后显示不可用提示，不会回退到候选版本。文本和应用选择按账号保存草稿。

应用上架成功后提供可选「发动态」入口，预填作品介绍和公开应用卡片；作品管理页也能主动发动态。上架本身不自动发帖，动态需要作者确认发布。

作者主页可从用户帖子、评论和市场作者名称进入，匿名浏览。GET /v1/profiles/:authorId 聚合公开头像昵称、官方标记、首批动态和该作者已上架应用，不返回邮箱、凭证或私有作品。后续动态使用 GET /v1/posts?authorId=...&cursor=...，每页最多 50 条；早期沿用时间线存储，单页最多扫描 500 条并返回扫描游标，稀疏作者页面可能不足 50 条，继续分页不会漏帖。市场支持 authorId 过滤，仅返回显式公开条目。主页保留自定义下拉刷新，进入动态详情后返回会刷新互动状态；关注功能尚未实现。

站内通知仅包含评论和回复。评论事务同时写入接收人的通知及未读数；通知动态作者和被回复评论作者，按接收人去重并排除操作者。请求重试不重复通知；删除评论、动态时清理通知及未读数。通知以评论 ID 标识，只能本人读取和标记已读。

- GET /v1/notifications：登录分页，每页 50 条，最新在前，返回 unreadCount。
- GET /v1/notifications/unread：登录读取未读数。
- POST /v1/notifications/read：{ids: [...]} 标记选定通知，{} 标记请求开始前的全部通知；幂等更新计数，后续新通知保持未读。
- GET /v1/posts/:id?commentId=...：从指定评论开始返回详情；评论已删除时返回 404，不误跳到其他评论。

动态页铃铛显示未读数，底部动态 Tab 显示未读点。前台登录状态每 30 秒同步未读数，回到前台立即同步；时间线响应也附带未读数，旧请求不能覆盖标记已读后的结果。通知页保留自定义下拉刷新，按账号缓存首批通知；换账号或退出时清除当前显示。点击通知标记已读并打开对应评论，复用同次详情响应避免再次请求。暂不接系统推送、点赞通知和关注通知。
