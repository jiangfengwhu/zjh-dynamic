# 页面请求聚合建议

## 已落地：作品列表聚合

`GET /v1/works` 已返回制作摘要 status、分享状态 sharing、更新时间 updatedAt 和接回凭据。客户端展示本地记录后读取一次汇总，不再逐作品发起 market/workshop status 请求。`?refresh=1` 用于下拉刷新。

服务端保存按应用、账号、session、制作轮次、阶段和候选版本匹配的摘要；活跃任务缓存 20 秒，已完成且有可体验候选包的任务缓存 5 分钟。相同查询合并，后台刷新最多并发 4 个，Jules 查询限时 6 秒。首次读取与手动刷新最多等待 6.5 秒，其他情况先返回缓存；过期、失败或未完成刷新的项带 stale 标记，不阻塞其他作品。

列表不查询 GitHub；进入工坊的原有交付流程仍记录源码证明，已有匹配证明时不重复请求 GitHub。缺失 session 的恢复在后台执行。授权写操作仍使用原有权限和实时状态检查；私有响应设置 private,no-store。缓存只在同一账号下使用，客户端根据当前健康加载的 releaseId 判断待体验/已体验。

## 已落地：工坊详情聚合

`POST /v1/workshop` 的 `action: detail` 在验证作者、制作 token 和 session 后，一次返回会话、活动记录、交付状态和公开版本。只查询一次 Jules session；分支证明在后台补全，不阻塞体验。候选发布不会改变公开版本。

Jules 活动接口没有文档化的排序或时间过滤参数，因此首批沿用最多四页、每页 100 条的有界读取，剩余记录使用 `action: activities` 和 pageToken 按需加载。活动按 session state/updateTime 缓存 30 秒，最多缓存 32 个会话。同步活动失败返回 stale，不把同步故障当作制作失败。

宿主合并接回、轮询和交付检查，4 秒内相同应用、账号、session 和制作记录的请求复用。缓存仅用于展示；制作和发布操作仍由实时权限、轮次和版本校验保护。

Jolly 只加载选中的工坊，恢复输入草稿、制作记录和滚动位置。前台且页面可见时，制作中每 5 秒同步；代码完成但候选包未到时每 15 秒等待交付。终态停止轮询，返回页面或恢复前台再同步。交付区区分待体验、已打开和已公开，并保留失败恢复入口。

市场分页仍是后续工作。以下保留本次优化前的链路分析和设计方向。

## 当前链路

- 市场列表已经由 `/v1/market` 返回清单和作者信息，无需客户端逐应用请求。
- 我的作品页面先由 `/v1/works` 接回记录，再对每个作品调用 `/v1/market` 的 status 与 `/v1/workshop` 的 status。缓存失效时约为 `1 + 2N` 个请求；进入工坊还会查询 session 和 activities。
- 两个 status 请求都带账号鉴权。同一应用的 POST 由服务端按 appId 排队，因此客户端 Promise.all 不代表这两个请求在服务端并行执行。
- workshop status 会请求 Jules；已完成时还可能访问 GitHub 查交付分支。`/v1/works` 对缺失 session 的记录会串行扫描 Jules 会话。列表展示被这些外部服务延迟影响。

## 第一优先级：作品列表聚合

扩展现有 `/v1/works`，一次返回每个作品的制作摘要、可体验版本、已分享版本和更新时间，保留接回制作所需的宿主私有字段。客户端提交当前已加载版本，或在客户端用 releaseId 判断待体验/已体验。目标为一次请求，不再逐作品调用两个 status。

实现采用服务端内部函数复用现有权限与交付判断，避免通过 HTTP 调用自己。账号只鉴权一次，作品只从当前用户的 owner 索引读取。候选版本只返回给作者；市场和普通更新仍消费公开版本。

列表返回服务端保存的状态摘要。活跃任务可使用短缓存、相同请求合并和有限并发刷新；单个 Jules/GitHub 请求失败时返回该作品 stale 标记，其他作品仍正常显示。已完成且候选版本/session 更新时间未变化时复用交付结果。显式继续制作、发布、撤回等写操作必须重新检查权限和当前状态，不复用列表缓存作授权依据。

缺失 session 的恢复单独后台执行，不让普通列表请求等待扫描全部 Jules 会话。已保存的源码证明/分支优先复用，避免每次列表刷新都请求 GitHub。

## 第二优先级：工坊详情聚合

增加单应用详情读取，一次返回 session、最近 activities、交付摘要和分享状态。服务端复用一次 session 查询；activities 只读取最近需要的页，历史按需分页。列表不返回聊天活动或完整日志。

## 后续

市场保持匿名可浏览；增加分页与条件请求，作者资料可使用短缓存。安装清单、大包和静态头像继续从 CDN 读取，不塞进页面聚合响应。先落地作品列表聚合，不额外拆独立 BFF 服务或引入 GraphQL。

验收指标：记录单次页面刷新请求数、p50/p95 延迟、Jules/GitHub 请求数、缓存命中率与 stale 比例。当前请求数量来自代码链路分析，尚未采集线上延迟分布。
